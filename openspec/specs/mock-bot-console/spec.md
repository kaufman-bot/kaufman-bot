# mock-bot-console Specification

## Purpose

Консоль мок-сервера бота: веб-интерфейс оператора (симулирует бота) со списком пользователей, переключением между их диалогами и отправкой ответов от имени бота; живое уведомление о новых сообщениях пользователей.

## Requirements

### Requirement: Доступ к API мок-сервера по роли ADMIN

Все эндпоинты мок-сервера бота SHALL требовать валидный API-ключ пользователя с ролью `ADMIN`: без ключа — `401`, с ключом пользователя без роли `ADMIN` — `403`. Ответ `403` для не-админа соответствует поведению существующего административного API проекта.

#### Scenario: Вход админским ключом

- **WHEN** запрос к эндпоинту мок-сервера выполнен с ключом пользователя с ролью `ADMIN`
- **THEN** доступ разрешён

#### Scenario: Вход пользовательским ключом

- **WHEN** запрос к эндпоинту мок-сервера выполнен с ключом пользователя с ролью `USER`
- **THEN** ответ `403` с телом ошибки, данные не возвращаются

#### Scenario: Запрос без ключа

- **WHEN** запрос к эндпоинту мок-сервера выполнен без API-ключа
- **THEN** ответ `401` с телом ошибки

### Requirement: Список пользователей с диалогами

Система SHALL предоставлять эндпоинт `GET /api/v1/mock-bot/conversations`, который возвращает список пользователей с их диалогами: пользователь (id, email), последнее сообщение (текст, отправитель, время), счётчик непрочитанных сообщений пользователя и время последней активности; список отсортирован по времени последней активности (сначала свежие).

#### Scenario: Есть диалоги

- **WHEN** у пользователей есть сообщения
- **THEN** ответ `200` содержит список, отсортированный по времени последнего сообщения (сначала свежие), с корректными счётчиками непрочитанных

#### Scenario: Диалогов нет

- **WHEN** ни один пользователь ещё не писал боту
- **THEN** ответ `200` содержит пустой список

### Requirement: История диалога выбранного пользователя

Система SHALL предоставлять эндпоинт `GET /api/v1/mock-bot/conversations/{userId}/messages`, который возвращает сообщения диалога указанного пользователя в хронологическом порядке; при чтении все непрочитанные сообщения пользователя в этом диалоге помечаются прочитанными (счётчик непрочитанных обнуляется).

#### Scenario: Оператор открыл диалог

- **WHEN** оператор запрашивает историю диалога пользователя
- **THEN** ответ `200` содержит сообщения в хронологическом порядке, и счётчик непрочитанных этого пользователя в списке становится равен нулю

#### Scenario: Несуществующий пользователь

- **WHEN** оператор запрашивает историю диалога по несуществующему userId
- **THEN** ответ `404` с телом ошибки

### Requirement: Ответ от имени бота

Система SHALL предоставлять эндпоинт `POST /api/v1/mock-bot/conversations/{userId}/messages`, который добавляет сообщение отправителя `BOT` в диалог указанного пользователя; сообщение SHALL быть доступно пользователю в истории и SSE-потоке его чата. Ответ может включать упорядоченный набор inline-кнопок (каждая с `title` и `callback_data`); текст `content` необязателен, если приложена хотя бы одна кнопка. Кнопки сохраняются как снимок сообщения и возвращаются вместе с ним.

#### Scenario: Успешный ответ оператора

- **WHEN** оператор отправляет непустой текст для диалога существующего пользователя
- **THEN** ответ `201` содержит созданное сообщение (отправитель `BOT`), и оно доставлено в чат пользователя

#### Scenario: Ответ только с кнопками (без текста)

- **WHEN** оператор отправляет ответ без текста, но с хотя бы одной корректной кнопкой
- **THEN** ответ `201` содержит созданное сообщение `BOT` с приложенными кнопками в переданном порядке, и оно доставлено в чат пользователя

#### Scenario: Ответ текстом вместе с кнопками

- **WHEN** оператор отправляет непустой текст и набор кнопок
- **THEN** ответ `201` содержит сообщение `BOT`, у которого есть и текст, и кнопки

#### Scenario: Пустое сообщение без кнопок

- **WHEN** текст пуст или отсутствует и при этом набор кнопок пуст
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Валидация текста ответа

- **WHEN** текст ответа длиннее 4000 символов
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Некорректные кнопки ответа

- **WHEN** хотя бы одна кнопка ответа имеет пустой `title` или пустой `callback_data` либо превышены лимиты кнопок
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Ответ несуществующему пользователю

- **WHEN** оператор отправляет ответ по несуществующему userId
- **THEN** ответ `404` с телом ошибки

### Requirement: SSE-поток новых сообщений пользователей

Система SHALL предоставлять SSE-поток `GET /api/v1/mock-bot/stream` (доступ по API-ключу с ролью `ADMIN`: заголовок `x-api-key` либо query-параметр `apiKey`), который доставляет оператору событие при каждом новом сообщении пользователя, чтобы обновлять список диалогов и открытую переписку без перезагрузки страницы. Событие по умолчанию (`message`) содержит данные нового сообщения и его диалога.

#### Scenario: Пользователь написал боту

- **WHEN** пользователь отправляет сообщение в свой диалог
- **THEN** подключённый оператор получает SSE-событие с этим сообщением и идентификатором диалога

### Requirement: Интерфейс консоли мок-сервера

Фронтенд SHALL предоставлять страницу `/mock-bot` со списком пользователей (порядок по последней активности, счётчик непрочитанных) и перепиской выбранного пользователя; оператор переключается между пользователями кликом по списку и отправляет ответ от имени бота; новые сообщения пользователей появляются без перезагрузки страницы. Доступ — только после входа ключом с ролью `ADMIN`; при ключе без роли `ADMIN` показывается отказ в доступе.

#### Scenario: Переключение между пользователями

- **WHEN** оператор выбирает другого пользователя в списке
- **THEN** в панели переписки отображается диалог выбранного пользователя

#### Scenario: Ответ через интерфейс

- **WHEN** оператор отправляет непустой текст со страницы консоли
- **THEN** сообщение появляется в переписке выбранного пользователя и доставляется ему

#### Scenario: Появление нового сообщения пользователя без перезагрузки

- **WHEN** пользователь отправил сообщение, пока открыт его диалог
- **THEN** сообщение появляется в переписке оператора без перезагрузки страницы

#### Scenario: Доступ не-админа

- **WHEN** вошедший пользователь с ролью `USER` открывает `/mock-bot`
- **THEN** показывается отказ в доступе, данные диалогов не отображаются

### Requirement: Конструктор кнопок в консоли

Фронтенд консоли `/mock-bot` SHALL позволять оператору динамически добавлять несколько кнопок в рабочую область, задавать каждой `title` и `callback_data`, а также редактировать и удалять кнопки до отправки. Отправляемое сообщение бота SHALL нести текущий набор кнопок рабочей области.

#### Scenario: Добавление и редактирование кнопок

- **WHEN** оператор добавляет кнопку и меняет её `title`/`callback_data` в рабочей области
- **THEN** набор кнопок консоли отражает изменения до отправки, ничего не сохраняя на сервере

#### Scenario: Удаление кнопки до отправки

- **WHEN** оператор удаляет кнопку из рабочей области
- **THEN** кнопка исключается из набора и не будет отправлена

#### Scenario: Отправка сообщения с активной клавиатурой

- **WHEN** оператор отправляет сообщение, имея в рабочей области ненулевой набор кнопок
- **THEN** к созданному сообщению бота приложены эти кнопки

### Requirement: Управление пресетами в консоли

Фронтенд консоли `/mock-bot` SHALL позволять оператору сохранить текущий набор кнопок как именованный пресет, загрузить существующий пресет в рабочую область (сделать активным), изменить и удалить пресет. Доступны SHALL быть только пресеты текущего админа.

#### Scenario: Сохранение набора как пресета

- **WHEN** оператор сохраняет текущий набор кнопок под именем
- **THEN** пресет появляется в списке пресетов консоли

#### Scenario: Загрузка пресета в рабочую область

- **WHEN** оператор выбирает существующий пресет активным
- **THEN** его кнопки заполняют рабочую область и будут приложены к следующему отправленному сообщению

#### Scenario: Сохранение изменённого набора в загруженный пресет

- **WHEN** оператор загрузил пресет в рабочую область, изменил набор кнопок и нажимает «Сохранить изменения»
- **THEN** отправляется `PATCH` с обновлёнными кнопками этого пресета (имя не меняется), список консоли отражает новые кнопки, а уже отправленные сообщения сохраняют прежний снимок кнопок

#### Scenario: Удаление пресета из консоли

- **WHEN** оператор удаляет свой пресет
- **THEN** он исчезает из списка, а уже отправленные сообщения сохраняют свои кнопки

### Requirement: Отображение кнопок и нажатий в консоли

Фронтенд консоли `/mock-bot` SHALL отображать кнопки у сообщений бота в переписке и показывать нажатия кнопок пользователем как сообщения отправителя `USER` (с текстом `callback_data`) в открытой переписке без перезагрузки страницы.

#### Scenario: Кнопки сообщения бота видны оператору

- **WHEN** оператор отправил сообщение с кнопками
- **THEN** в переписке консоли это сообщение отображается с теми же кнопками

#### Scenario: Нажатие пользователя видно оператору

- **WHEN** пользователь нажимает кнопку в своём чате
- **THEN** в открытой переписке консоли появляется сообщение отправителя `USER` с текстом `callback_data` без перезагрузки страницы
