# Proposal: add-chat-channel-visibility

## Why

Сообщения диалога ходят по разным транспортам: пользователь пишет из веб-чата или из Telegram (через один из нескольких Telegram-ботов), а ответы бота доставляются из мок-консоли оператора или плагинами — либо только в веб-чат, либо дополнительно в Telegram. Ни пользователь, ни оператор не видят, по какому каналу прошло конкретное сообщение: в консоли `/mock-bot` не видно, откуда писал пользователь, а в чате `/chat` не видно, куда именно доставлен ответ (в Telegram или только в веб-чат). При нескольких Telegram-ботах и нескольких операторах-админах отправители визуально неразличимы.

## What Changes

- Каждое сообщение при записи получает снимок канала:
  - сообщение `USER` — канал, с которого оно поступило (`WEB` или `TELEGRAM`) и имя Telegram-бота, принявшего сообщение;
  - сообщение `BOT` — канал доставки (`WEB` — только веб-чат/мок-цель, `TELEGRAM` — переслано боту) и имя бота-получателя.
- Ответ, отправленный из мок-консоли оператора, дополнительно фиксирует email оператора-админа, отправившего сообщение (разные операторы различимы).
- Поля канала добавляются в DTO сообщений и SSE-события (`/chat`, `/mock-bot`), а также в сводку диалогов консоли (канал последнего сообщения); swagger.json и SDK перегенерируются.
- Страница `/chat`: под каждым сообщением видна канальная отметка («отправлено из…» для своих, «доставлено в…» для ответов бота) с именем бота; отправитель ответа подписывается email оператора (если ответ из консоли) или «Бот»; фон/акцент сообщений определяется идентичностью отправителя/получателя (мок-сервер, конкретный бот, оператор) — сообщения разных ботов различимы между собой, а не только текстом бейджа.
- Консоль `/mock-bot`: у входящих сообщений пользователя виден канал и имя бота; у ответов — email оператора и канал доставки; в списке диалогов у превью последнего сообщения виден канал; визуальное различение отправителей по идентичности (цвет на конкретного бота/оператора/мок).
- Сообщения, записанные до нововведения (без канала), отображаются без канальной отметки — не ломают существующую историю.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `user-chat`: добавляется требование об отображении канала и имени бота в чате пользователя — откуда отправлено собственное сообщение и куда доставлен ответ бота (веб-чат / Telegram + имя бота), подпись оператора у ответов консоли, визуальное различение отправителей.
- `mock-bot-console`: добавляется требование об отображении канала входящих сообщений пользователя (веб-чат / Telegram + имя бота), фиксации и отображения email оператора у ответов консоли, канала последнего сообщения в списке диалогов.

## Impact

- **Prisma**: enum `MessageChannel` (`WEB`/`TELEGRAM`), nullable-поля снимка на `Message` (`channel`, `botName`, `operatorEmail`); миграция + `prisma generate`.
- **Backend**: `ChatService.sendMessage`/`submitButtonCallback` (параметр источника: веб-контроллер и Telegram-мост), `MockBotService.replyAsBot` (email оператора + снимок доставки), `BotPluginsService` (снимок доставки), `TelegramBridgeService` (передаёт имя бота), новый сервис-резолвер канала доставки; `ChatEvent` и DTO (`ChatMessageDto`, `ChatStreamEventDto`, `MockBotStreamEventDto`, `ConversationSummaryDto`); регистрация в `app.module.ts`; swagger.json + SDK (`generate:openapi-ts`).
- **Frontend**: `chat.service.ts`, `chat/chat.component.ts`, `mock-bot.service.ts`, `mock-bot/mock-bot.component.ts` — интерфейсы, канальные бейджи, подписи отправителей, визуальное различение (фон/акцент по каналу и отправителю).
- **Тесты**: юнит-тесты сервисов и компонентов, e2e (форма DTO меняется — проверить точные сравнения), регенерация SDK.
- **Документация**: `backend/README.md`, `frontend/README.md`, `docs/architecture.md`.
