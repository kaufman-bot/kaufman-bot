# Spec Delta: mock-bot-console

## ADDED Requirements

### Requirement: Канальные данные сообщений в API консоли

История, SSE-поток и список диалогов консоли SHALL включать канальный снимок: в каждом сообщении — `channel` (`WEB`, `TELEGRAM` или `null`), `botName` и `operatorEmail`; в сводке диалога — `lastMessageChannel` последнего сообщения. Для `USER` (включая нажатия кнопок) канал — откуда написано; для `BOT` — куда доставлено в момент создания.

#### Scenario: Сообщение пользователя из Telegram

- **WHEN** пользователь отправляет текст через привязанного Telegram-бота
- **THEN** оператор получает сообщение (в истории и SSE-событии) с `channel = TELEGRAM` и `botName` с именем этого бота

#### Scenario: Сообщение пользователя из веб-чата

- **WHEN** пользователь отправляет сообщение со страницы `/chat`
- **THEN** оператор получает сообщение с `channel = WEB` и `botName = null`

#### Scenario: Нажатие кнопки из Telegram

- **WHEN** пользователь нажимает inline-кнопку в Telegram (callback-запрос через бота)
- **THEN** оператор видит в консоли сообщение нажатия с `channel = TELEGRAM` и именем бота

#### Scenario: Канал последнего сообщения в списке диалогов

- **WHEN** оператор открывает список диалогов консоли
- **THEN** каждый диалог содержит `lastMessageChannel` — канал его последнего сообщения (или `null`, если диалог пуст или сообщение старое)

### Requirement: Фиксация оператора в ответах консоли

Эндпоинт `POST /api/v1/mock-bot/conversations/{userId}/messages` SHALL записывать email аутентифицированного админа, отправившего ответ, в канальный снимок созданного сообщения `BOT` (`operatorEmail`). Ответ эндпоинта и все последующие чтения этого сообщения SHALL возвращать зафиксированный `operatorEmail`. Автоответы плагинов SHALL иметь `operatorEmail = null`.

#### Scenario: Ответ оператора подписывается его email

- **WHEN** админ с известным email отправляет ответ из консоли
- **THEN** ответ `201` содержит созданное сообщение с `operatorEmail`, равным email этого админа

#### Scenario: Email оператора сохраняется в истории

- **WHEN** оператор позже перечитывает историю диалога с его ответом
- **THEN** сообщение ответа содержит тот же `operatorEmail`

#### Scenario: Автоответ плагина без оператора

- **WHEN** плагин автоматически отвечает на сообщение пользователя
- **THEN** созданный ответ содержит `operatorEmail = null`

### Requirement: Отображение канала и отправителей в консоли

Фронтенд консоли SHALL показывать: у сообщений пользователя — бейдж источника (веб-чат или Telegram с именем бота), у ответов бота — подпись отправителя (email оператора либо «Бот») и бейдж доставки, в списке диалогов — отметку канала у превью. Сообщения разных отправителей/получателей SHALL визуально различаться, в том числе сообщения и ответы, прошедшие разными Telegram-ботами, — не только текстом отметки; сообщения без снимка — без отметки.

#### Scenario: Источник входящего сообщения виден

- **WHEN** в открытой переписке есть сообщение пользователя из Telegram-бота «Support Bot»
- **THEN** под сообщением отображается отметка «Telegram · Support Bot»

#### Scenario: Подпись оператора на его ответах

- **WHEN** в переписке есть ответ бота, отправленный оператором из консоли
- **THEN** отправитель сообщения подписан email этого оператора и видна отметка канала доставки

#### Scenario: Канал в превью списка диалогов

- **WHEN** последнее сообщение диалога пришло из Telegram
- **THEN** превью этого диалога в списке содержит отметку канала Telegram

#### Scenario: Разные отправители визуально различимы

- **WHEN** в переписке есть сообщения пользователя, ответы разных операторов и автоответ плагина
- **THEN** эти группы сообщений отличаются визуально (фон/акцент и подпись отправителя)

#### Scenario: Сообщения разных ботов различимы между собой

- **WHEN** в консоли есть сообщения и/или ответы, прошедшие через два разных Telegram-бота (например, после смены цели пользователя)
- **THEN** эти сообщения отличаются визуально (фон/акцент), а не только текстом канальной отметки
