# Spec Delta: user-chat

## ADDED Requirements

### Requirement: Канальные данные сообщений в API чата

История `GET /api/v1/chat/messages` и SSE-поток `GET /api/v1/chat/stream` SHALL включать в каждое сообщение канальный снимок: `channel` (`WEB`, `TELEGRAM` или `null`), `botName` (имя Telegram-бота канала или `null`) и `operatorEmail` (email оператора для ответов консоли, иначе `null`). Для `USER` канал — откуда отправлено сообщение; для `BOT` — куда доставлено в момент создания.

#### Scenario: Сообщение, отправленное из веб-чата

- **WHEN** пользователь отправляет сообщение со страницы `/chat`
- **THEN** созданное сообщение и его SSE-событие содержат `channel = WEB` и `botName = null`

#### Scenario: Сообщение, отправленное из Telegram

- **WHEN** пользователь отправляет текст через привязанного Telegram-бота
- **THEN** созданное сообщение содержит `channel = TELEGRAM` и `botName` с именем этого бота

#### Scenario: Ответ бота при активной привязке

- **WHEN** бот добавляет ответ в диалог пользователя, привязанного к активному Telegram-боту с привязанным чатом
- **THEN** ответ содержит `channel = TELEGRAM` и `botName` с именем бота-получателя

#### Scenario: Ответ бота для мок-цели

- **WHEN** бот добавляет ответ в диалог пользователя без привязки к Telegram-боту
- **THEN** ответ содержит `channel = WEB` и `botName = null`

#### Scenario: Старое сообщение без канала

- **WHEN** пользователь запрашивает историю, содержащую сообщения, записанные до появления канального снимка
- **THEN** такие сообщения возвращаются с `channel = null`, `botName = null`, `operatorEmail = null` и не теряются из истории

### Requirement: Отображение канала и отправителя в чате пользователя

Фронтенд страницы `/chat` SHALL показывать под каждым сообщением канальную отметку (у своих — канал отправки, у ответов бота — канал доставки с именем бота), подписывать ответы бота email оператора либо «Бот» и визуально различать сообщения разных отправителей/получателей, в том числе ответы, доставленные разными Telegram-ботами, — не только текстом отметки. Сообщения без канального снимка SHALL отображаться без отметки.

#### Scenario: Канал доставки ответа виден

- **WHEN** в чат доставлен ответ бота с `channel = TELEGRAM` и `botName = «Support Bot»`
- **THEN** под сообщением отображается отметка доставки в Telegram с именем «Support Bot»

#### Scenario: Ответ только в веб-чате

- **WHEN** доставлен ответ бота с `channel = WEB` (пользователь без привязки)
- **THEN** под сообщением отображается отметка доставки в веб-чат без имени бота

#### Scenario: Подпись оператора у ответа консоли

- **WHEN** доставлен ответ бота, отправленный оператором из мок-консоли
- **THEN** отправитель сообщения подписан email этого оператора

#### Scenario: Свой канал отправки виден

- **WHEN** пользователь отправил сообщение через Telegram, а затем открыл страницу `/chat`
- **THEN** под его сообщением отображается отметка отправки через Telegram с именем бота

#### Scenario: Разные отправители визуально различимы

- **WHEN** в переписке есть сообщения пользователя, ответа мок-сервера и ответа, доставленного через Telegram-бота
- **THEN** эти группы сообщений отличаются визуально (фон/акцент и подпись отправителя)

#### Scenario: Ответы разных ботов различимы между собой

- **WHEN** в переписке есть ответы, доставленные через два разных Telegram-бота (например, после смены цели пользователя)
- **THEN** эти сообщения отличаются визуально (фон/акцент), а не только текстом канальной отметки

#### Scenario: Сообщение без канала

- **WHEN** в истории есть сообщение с `channel = null`
- **THEN** оно отображается без канальной отметки, но с обычной подписью отправителя
