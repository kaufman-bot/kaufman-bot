# Spec Delta

## ADDED Requirements

### Requirement: Кнопка «Ответить» на сообщениях пользователя

Фронтенд консоли `/mock-bot` SHALL отображать кнопку «Ответить» на каждом сообщении отправителя `USER` в открытой переписке (как текстовых, так и нажатиях кнопок). Нажатие кнопки SHALL переводить композер в режим ответа: над полем ввода отображается индикатор с снимком выбранного сообщения и способом отменить режим. Отменённый или завершённый режим ответа SHALL NOT влиять на последующие ответы.

#### Scenario: Вход в режим ответа

- **WHEN** оператор нажимает «Ответить» на сообщении пользователя
- **THEN** над композером появляется индикатор ответа с содержимым выбранного сообщения, и следующий отправленный ответ будет связан с этим сообщением

#### Scenario: Отмена режима ответа

- **WHEN** оператор отменяет режим ответа по индикатору
- **THEN** индикатор исчезает и следующий ответ отправляется без связи с каким-либо сообщением

#### Scenario: Сброс режима после отправки

- **WHEN** оператор отправил ответ, находясь в режиме ответа
- **THEN** режим сбрасывается, индикатор исчезает

#### Scenario: Сброс режима при смене диалога

- **WHEN** оператор переключается на диалог другого пользователя, находясь в режиме ответа
- **THEN** режим сбрасывается и не переносится на новый диалог

### Requirement: Ответ с цитатой сообщения пользователя

Система SHALL позволять оператору при `POST /api/v1/mock-bot/conversations/{userId}/messages` дополнительно передать `replyToMessageId` — идентификатор сообщения отправителя `USER` из диалога этого же пользователя. Созданный ответ бота SHALL нести ссылку на это сообщение и доставляться пользователю (история и SSE-поток) со снимком цитируемого сообщения независимо от канала доставки. Ссылка на несуществующее, чужое или не-пользовательское сообщение SHALL отклоняться с `400` без сохранения ответа.

#### Scenario: Успешный ответ с цитатой

- **WHEN** оператор отправляет ответ с `replyToMessageId` существующего сообщения пользователя из этого диалога
- **THEN** ответ `201` содержит сообщение `BOT`, связанное с указанным сообщением, и оно доставлено в чат пользователя

#### Scenario: Несуществующая цель цитаты

- **WHEN** оператор отправляет ответ с `replyToMessageId`, которого нет в системе
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Цель цитаты из чужого диалога

- **WHEN** оператор отправляет ответ с `replyToMessageId` сообщения, принадлежащего диалогу другого пользователя
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Цель цитаты — не сообщение пользователя

- **WHEN** оператор отправляет ответ с `replyToMessageId`, указывающим на сообщение отправителя `BOT`
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

### Requirement: Отображение цитат в переписке консоли

Фронтенд консоли `/mock-bot` SHALL отображать в переписке снимок цитируемого сообщения у ответов бота, созданных с ссылкой на сообщение пользователя; снимок SHALL быть виден как при загрузке истории, так и при поступлении ответа в реальном времени. Ответы бота без ссылки SHALL отображаться как обычно, без блока цитаты.

#### Scenario: Цитата видна у ответа с ссылкой

- **WHEN** в переписке консоли появляется ответ бота, созданный с `replyToMessageId`
- **THEN** над его текстом отображается снимок цитируемого сообщения пользователя

#### Scenario: Обычный ответ без цитаты

- **WHEN** в переписке консоли появляется ответ бота без ссылки на сообщение
- **THEN** он отображается как обычно, без блока цитаты

### Requirement: Индикация доставки у ответов бота в консоли

Фронтенд консоли `/mock-bot` SHALL отображать у каждого ответа бота пометку каналов доставки на основе `deliveredTo` (с именем бота из снимка, когда оно известно): «веб + Telegram» для двойной доставки и «веб» для доставки только в веб. Пометка SHALL быть видна как при загрузке истории, так и при поступлении ответа в реальном времени.

#### Scenario: Пометка двойной доставки видна

- **WHEN** в переписке появляется ответ бота с `deliveredTo`, содержащим оба канала
- **THEN** у сообщения отображается пометка «веб + Telegram» (с именем бота, когда оно известно)

#### Scenario: Веб-only ответ помечается одним каналом

- **WHEN** в переписке появляется ответ бота с `deliveredTo`, содержащим только `WEB`
- **THEN** пометка указывает доставку только в веб
