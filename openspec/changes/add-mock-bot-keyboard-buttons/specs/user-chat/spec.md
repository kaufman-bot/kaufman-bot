# Spec Delta

## MODIFIED Requirements

### Requirement: История диалога пользователя

Система SHALL предоставлять эндпоинт `GET /api/v1/chat/messages` (доступ по API-ключу), который возвращает сообщения диалога вошедшего пользователя в хронологическом порядке (по возрастанию времени создания), включая сообщения пользователя и ответы бота (с их кнопками). Сообщения, порождённые нажатием кнопок самим пользователем, SHALL НЕ возвращаться в истории пользователя (они видны только оператору).

#### Scenario: Диалог без сообщений

- **WHEN** пользователь ни разу не отправлял сообщений
- **THEN** ответ `200` содержит пустой список сообщений

#### Scenario: Диалог с сообщениями

- **WHEN** в диалоге есть сообщения пользователя и бота
- **THEN** ответ `200` содержит их в хронологическом порядке

#### Scenario: Нажатия кнопок скрыты из истории пользователя

- **WHEN** пользователь ранее нажимал кнопки, породившие сообщения-коллбэки
- **THEN** эти сообщения отсутствуют в истории, возвращаемой пользователю

## ADDED Requirements

### Requirement: Отображение кнопок в сообщении бота

Фронтенд страницы `/chat` SHALL отображать под текстом сообщения бота его inline-кнопки, где подпись кнопки равна её `title`. Кнопки SHALL быть доступны для нажатия.

#### Scenario: Кнопки видны под сообщением бота

- **WHEN** в чат доставлено сообщение бота с набором кнопок
- **THEN** под сообщением отображаются кнопки с подписями `title`

#### Scenario: Сообщение без кнопок

- **WHEN** сообщение бота не имеет кнопок
- **THEN** оно отображается как обычно, без панели кнопок

### Requirement: Отправка callback_data по нажатию кнопки

Когда пользователь нажимает кнопку сообщения бота, фронтенд SHALL отправить её `callback_data` на сервер от имени вошедшего пользователя; сервер SHALL сохранить это как сообщение отправителя `USER` в диалоге пользователя.

#### Scenario: Нажатие сохраняет коллбэк оператору

- **WHEN** пользователь нажимает кнопку с `callback_data`
- **THEN** в диалоге создаётся сообщение отправителя `USER` с текстом `callback_data`, доступное оператору в консоли

### Requirement: Отсутствие эха и автоответа на нажатие кнопки у пользователя

Сообщение, порождённое нажатием кнопки, SHALL НЕ отображаться в чате самого пользователя: оно не появляется в его списке сообщений ни сразу, ни через SSE-поток, ни при повторной загрузке истории. Нажатие кнопки SHALL НЕ вызывать автоматический ответ бота (плагины не реагируют на такие сообщения).

#### Scenario: Нет локального эха

- **WHEN** пользователь нажимает кнопку
- **THEN** в его чате не появляется новое сообщение от его имени

#### Scenario: Нет доставки через SSE

- **WHEN** коллбэк-сообщение пользователя создано на сервере
- **THEN** оно не доставляется в SSE-поток этого пользователя

#### Scenario: Плагины не отвечают на нажатие

- **WHEN** `callback_data` нажатой кнопки совпадает с условием срабатывания плагина (например `ping`)
- **THEN** автоматический ответ бота в диалоге не появляется
