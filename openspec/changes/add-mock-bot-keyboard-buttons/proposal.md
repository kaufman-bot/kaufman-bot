# Proposal

## Why

Консоль мок-сервера бота умеет отправлять пользователю только плоский текст, тогда как реальный Telegram-бот отвечает интерактивными inline-кнопками (сообщение + клавиатура с `text`/`callback_data`). Чтобы мок-сервер годился для отладки сценариев с кнопками, оператору нужно собирать клавиатуру из кнопок (title + callback_data), многократно переиспользовать её через сохраняемые пресеты и отправлять вместе с сообщением, а пользователь должен видеть эти кнопки в чате и по нажатию отправлять `callback_data` на сервер.

## What Changes

- **Кнопки у сообщения бота (мок-сервер → пользователь)**: ответ оператора из консоли мок-сервера может нести набор inline-кнопок; каждая кнопка имеет `title` (подпись на кнопке) и `callback_data` (payload, уходящий на сервер при нажатии). Кнопки «замораживаются» в момент отправки и остаются привязанными к сообщению, независимо от дальнейшей судьбы пресета.
- **Текст сообщения становится опциональным**: в `POST /api/v1/mock-bot/conversations/{userId}/messages` поле `content` более не обязательно — сообщение может состоять только из кнопок. **BREAKING** для строгого клиента: пустой запрос теперь валиден, если приложена хотя бы одна кнопка; сообщение без текста и без кнопок по-прежнему отвергается (`400`).
- **Динамический конструктор кнопок в консоли**: оператор добавляет/редактирует/удаляет несколько кнопок в рабочей области перед отправкой (пока ничего не сохраняя).
- **Пресеты кнопок (новая возможность)**: рабочий набор кнопок можно сохранить как именованный пресет, изменить и удалить; пресеты переиспользуются в разных диалогах с любыми пользователями. Пресеты **привязаны к оператору-админу** (владелец — создавший админ): каждый админ видит и меняет только свои пресеты. CRUD-эндпоинты пресетов закрыты ролью `ADMIN`.
- **Отправка активного пресета**: выбранный («активный») пресет в консоли прикладывается к отправляемому сообщению; оператор может отправить и ad-hoc набор кнопок, не сохраняя его.
- **Кнопки в чате пользователя**: сообщения бота с кнопками рендерятся в панели чата — `title` показывается на кнопке под текстом сообщения.
- **Нажатие кнопки = тихий callback**: по клику `callback_data` отправляется на сервер как сообщение пользователя (видно оператору в консоли), но **без эха в чате самого пользователя** (не появляется в его истории и SSE-потоке) и **без реакции плагинов**. Это отдельный сценарий, а не обычная отправка текста.
- Telegram-интеграция по-прежнему вне рамок; кнопки живут только в веб-чате и консоли мок-сервера.

Допущения, принятые без отдельного вопроса:

- Сообщение должно содержать хотя бы текст или хотя бы одну кнопку; полностью пустое сообщение (ни текста, ни кнопок) отвергается `400`.
- Кнопки отображаются одной горизонтальной строкой под текстом сообщения (раскладка в несколько рядов — вне рамок).
- Кнопки сообщения — это неизменяемый снимок на момент отправки; редактирование/удаление пресета не переписывает уже отправленные сообщения (как в Telegram, где клавиатура остаётся у сообщения).
- Обязательность и лимиты полей кнопок (`title`, `callback_data`) задаются в сервисах (глобального `ValidationPipe` в проекте нет); значения лимитов уточняются в design.md.
- Нажатие кнопки аутентифицируется ключом самого пользователя и попадает в его диалог как сообщение отправителя `USER` с пометкой «кнопочный» — оно видно оператору, но скрывается из пользовательского отображения.

## Capabilities

### New Capabilities

- `button-presets`: переиспользуемые наборы inline-кнопок оператора — модель пресета с привязкой к владельцу-админу, CRUD-эндпоинты под ролью `ADMIN`, область видимости «только свои пресеты», правила валидации кнопок и концепт «активный пресет», прикладываемый к отправляемому сообщению.

### Modified Capabilities

- `mock-bot-console`: ответ от имени бота теперь может нести набор inline-кнопок, а текст становится опциональным (хотя бы одно из текста/кнопок); интерфейс консоли получает конструктор кнопок (добавить/редактировать/удалить до отправки) и управление пресетами; оператор видит в консоли нажатия кнопок пользователя.
- `user-chat`: сообщения бота отображаются с кнопками (`title` на кнопке); нажатие кнопки отправляет её `callback_data` на сервер как «тихий» callback — без появления в истории/потоке самого пользователя и без автоответа плагинов.

## Impact

- **Схема БД** (только миграции Prisma): у `Message` — снимок кнопок (массив `{ title, callbackData }`, nullable JSON) и различение обычной отправки от кнопочного callback (например, enum `MessageKind { TEXT, BUTTON }` либо булев признак); новая модель `ButtonPreset` (`name`, `buttons` JSON, `ownerId` → `User`, `createdAt`/`updatedAt`) со связью `User.presets`. Значения enum/типы импортировать из `src/generated/prisma`.
- **Бэкенд** (`backend/`): расширение `MockBotReplyRequestDto` (опциональный `content`, массив кнопок) и `ChatMessageDto`/`MockBotStreamEventDto`/`ChatStreamEventDto` (кнопки, признак кнопочного сообщения); `MockBotService.replyAsBot` — сохранение кнопок; новый сервис и контроллер CRUD пресетов (регистрация в `AppModule`); пользовательский путь отправки — различение текста и кнопочного callback (без создания `BotPluginTask` и без публикации в пользовательский SSE); фильтрация кнопочных сообщений в `ChatService.getHistory`/`streamEvents`. Валидация — в сервисах.
- **Фронтенд** (`frontend/`): в консоли `/mock-bot` — конструктор кнопок и панель пресетов (создание/загрузка/редактирование/удаление, выбор активного пресета), рендер кнопок у сообщений бота и отображение нажатий пользователя; в `/chat` — рендер кнопок в пузырях сообщений бота и обработчик клика, отправляющий `callback_data` без локального эха. Обновить сервисы/типы (`mock-bot.service.ts`, `chat.service.ts`).
- **Swagger/SDK**: перегенерация `swagger.json` → OpenAPI SDK (`npm run start:dev` → `npm run generate:openapi-ts`) для новых операций и расширенных тел.
- **Тесты**: юнит (Vitest) — сервис консоли/пресетов и пользовательский путь с признаком callback; e2e (SDK на живом бэкенде) — отправка с кнопками и без текста, CRUD/область видимости пресетов, «тихий» характер нажатия (нет в истории пользователя, видно оператору, плагины не сработали); Jest фронта — конструктор/пресеты и рендер+клик кнопок.
