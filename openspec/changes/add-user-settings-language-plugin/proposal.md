# Proposal

## Why

У пользователя нет способа посмотреть и изменить свои настройки: всё поведение бота жёстко зафиксировано в коде, а единственное известное пользователю представление о профиле — таймзона, которую фронтенд синхронизирует молча. Первый реально нужный параметр — язык общения: часть пользователей русскоязычная, часть англоязычная, и дальше число настроек будет только расти. Нужен механизм, которым настройка просматривается и меняется внутри самого чата (без нового UI и без нового REST-экрана для пользователя), плюс место, где это значение хранится.

## What Changes

- У пользователя появляется активный язык (`ru` | `en`), по умолчанию `en`; значение хранится в профиле и отдаётся в контракте профиля.
- Новый плагин бота «настройки пользователя»: сообщение `/settings` возвращает текст с активным языком и inline-кнопки выбора языка (`Русский`, `English`), текущий помечен.
- Нажатие кнопки языка меняет активный язык пользователя и присылает сообщение-подтверждение уже на новом языке.
- Область payload `settings:language:` целиком закреплена за плагином настроек: код вне поддерживаемого перечня (`de`, пустой, список) тоже обрабатывается — приходит сообщение об отказе на оставшемся активном языке, а профиль не меняется. Payload чужих областей остаются необработанными (ответа нет).
- **BREAKING** (поведенческое): нажатие inline-кнопки перестаёт быть гарантированно «тихим» — коллбэк, который обрабатывает плагин, объявивший приём кнопок, порождает обычный ответ бота. Для кнопок, не принадлежащих таким плагинам (пресеты оператора), поведение прежнее: ответа нет.
- Контракт плагина расширяется: плагин может объявить приём коллбэков и вернуть вместо простого текста ответ с кнопками.
- Outbox-задача создаётся и для коллбэк-сообщений, поэтому смена языка, прерванная перезапуском, доводится до конца тем же recovery-sweep'ом.
- Вне рамок этого изменения: перевод остальных текстов бота (`pong`, `time`, сообщения консоли) на активный язык, выбор языка в веб-интерфейсе, другие настройки (тема, уведомления), язык интерфейса фронтенда.

## Capabilities

### New Capabilities

- `user-language`: хранение активного языка в профиле пользователя, значение по умолчанию `en`, выдача поля в контракте профиля и самообновление через `PATCH /auth/me`.
- `settings-plugin`: плагин чата, который показывает настройки по `/settings`, реагирует на нажатие кнопки выбора языка, меняет язык и подтверждает смену сообщением на новом языке; неподдерживаемый код в payload той же области получает сообщение об отказе вместо молчания.
- `bot-plugin-callbacks`: расширение контракта плагинов — объявление приёма нажатий кнопок и возврат ответа с кнопками; диспатч коллбэков только плагинам, объявившим приём, с той же exactly-once-доставкой через outbox.

### Modified Capabilities

- `user-chat`: требование об отсутствии автоответа на нажатие кнопки ограничивается кнопками, которые не обрабатываются плагинами; скрытие «эха» нажатия из истории и SSE пользователя сохраняется без изменений.

> Примечание о процессе: capability `bot-plugin-system` (`openspec/changes/add-bot-plugin-system/`) ещё не архивирована, поэтому правила диспатча коллбэков оформлены как новая capability `bot-plugin-callbacks`, а не как дельта к существующему основному спеку.

## Impact

- `backend/prisma/schema.prisma` + новая миграция Prisma: поле `language` у `User` (enum со значениями `ru`/`en`, дефолт `en`).
- `backend/src/plugins/`: новый `settings.plugin.ts`, расширенный `bot-plugin.interface.ts` (коллбэки, ответ с кнопками), изменённый `bot-plugins.service.ts` (диспатч по kind, персист кнопок ответа).
- `backend/src/services/chat.service.ts` + `chat.controller.ts`: коллбэк создаёт outbox-задачу и уходит в диспатчер плагинов.
- `backend/src/services/auth.service.ts` + `backend/src/dto/auth.dto.ts`: `language` в ответе профиля и в `PATCH /auth/me`.
- `backend/src/app.module.ts`: регистрация `SettingsPlugin` в фабрике `BOT_PLUGINS` (порядок = приоритет).
- Тесты: юнит-плейсы `backend/src/plugins/*.spec.ts`, `chat.service.spec.ts`, новые e2e-сценарии в `backend/test/`; спецификации `frontend` не затрагиваются (рендер кнопок сообщений бота и SSE уже есть).
- Документация: `README.md` (плагин `/settings`, поле `language`), `docs/architecture.md`, `BACKLOG.md` (вынос auto-registration плагинов и i18n остальных текстов).
