# Spec Delta

## Purpose

Активный язык пользователя: где значение хранится, какие значения допустимы, какое значение получают новые пользователи, и как пользователь может его прочитать или изменить через существующие контракты профиля. Язык определяет, на каком языке пользователю отвечают те возможности бота, которые поддерживают перевод.

## ADDED Requirements

### Requirement: Активный язык в модели пользователя

У каждого пользователя SHALL быть активный язык — одно из допустимых значений `ru` или `en`; по умолчанию (и для всех существующих пользователей на момент внедрения) SHALL быть `en`. Изменение схемы БД SHALL выполняться только миграцией Prisma.

#### Scenario: Новый пользователь получает язык по умолчанию

- **WHEN** создаётся аккаунт (регистрация или сид) без явного указания языка
- **THEN** активный язык пользователя — `en`, аккаунт работает как прежде

#### Scenario: Существующие пользователи после миграции

- **WHEN** миграция добавления поля языка применена к базе с уже существующими пользователями
- **THEN** у каждого существующего пользователя активный язык — `en`, других значений в поле нет

#### Scenario: Недопустимое значение не сохраняется

- **WHEN** в систему пытается попасть язык, отличный от `ru` и `en`
- **THEN** значение отклоняется на уровне валидации запроса, сохранённый язык не меняется

### Requirement: Активный язык в контракте профиля

Ответы `GET /api/v1/auth/me`, `POST /api/v1/auth/login`, `POST /api/v1/auth/register` и `PATCH /api/v1/auth/me` SHALL включать поле `language` пользователя со значением `ru` или `en` в составе части «пользователь».

#### Scenario: Профиль с выбранным языком

- **WHEN** у пользователя активный язык `ru` и запрашивается профиль
- **THEN** ответ содержит `language: "ru"`

#### Scenario: Профиль пользователя, не менявшего язык

- **WHEN** профиль запрашивается у пользователя, который никогда не менял язык
- **THEN** ответ содержит `language: "en"`

### Requirement: Смена активного языка владельцем ключа

Система SHALL принимать в `PATCH /api/v1/auth/me` необязательное поле `language` и, если оно передано, SHALL валидировать его (`ru` | `en`) и сохранять для владельца предъявленного API-ключа. Отсутствующее поле SHALL оставлять прежний язык; значение вне допустимого набора SHALL давать `400` без изменения данных. Ответ SHALL быть профилем в том же контракте, что и `GET /api/v1/auth/me`.

#### Scenario: Успешная смена языка

- **WHEN** владелец валидного ключа отправляет `PATCH /api/v1/auth/me` с `language: "ru"`
- **THEN** ответ `200` содержит профиль с `language: "ru"`, значение сохранено

#### Scenario: Поле не передано

- **WHEN** `PATCH /api/v1/auth/me` содержит только `timezone`
- **THEN** ответ `200`, активный язык пользователя остаётся прежним

#### Scenario: Недопустимое значение языка

- **WHEN** в теле `PATCH /api/v1/auth/me` передано `language: "de"`
- **THEN** ответ `400` с телом ошибки, язык не меняется

#### Scenario: Запрос без валидного ключа

- **WHEN** `PATCH /api/v1/auth/me` вызван без API-ключа или с недействительным ключом
- **THEN** ответ `401` с телом ошибки, язык не меняется
