# Spec Delta

## Purpose

Сид дефолтных пользователей для веб-чата: при старте приложения гарантируются два пользователя с ролью `USER` и их API-ключи, взятые из переменных окружения, — чтобы можно было сразу входить в чат без ручной регистрации.

## ADDED Requirements

### Requirement: Создание двух дефолтных USER-пользователей при старте

При запуске приложения система SHALL гарантировать наличие двух пользователей с ролью `USER` и прикреплёнными API-ключами, определённых переменными окружения `USER1_EMAIL`/`USER1_PASSWORD`/`USER1_API_KEY` и `USER2_EMAIL`/`USER2_PASSWORD`/`USER2_API_KEY` (email и ключ — идемпотентные ключи поиска, пароль хранится в хэшированном виде). Пользователи с этими ключами SHALL сразу иметь доступ к входу и чату.

#### Scenario: Переменные окружения заданы

- **WHEN** приложение стартует и все шесть переменных заданы
- **THEN** в системе существуют два пользователя с ролью `USER` и их API-ключами из переменных

#### Scenario: Повторный запуск с теми же переменными

- **WHEN** приложение перезапускается с теми же значениями переменных
- **THEN** дубликаты пользователей и ключей не создаются; существующие записи не теряются

### Requirement: Пропуска сида без переменных окружения

Сид дефолтных пользователей SHALL быть опциональным: если переменные не заданы (полностью или частично для конкретного пользователя), система SHALL пропускать создание соответствующего пользователя с предупреждением в логе и продолжать работу приложения.

#### Scenario: Переменные отсутствуют

- **WHEN** приложение стартует без части или без всех переменных `USER1_*`/`USER2_*`
- **THEN** соответствующий пользователь не создаётся, в лог пишется предупреждение, приложение продолжает работу

#### Scenario: Частично заданные переменные одного пользователя

- **WHEN** у одного пользователя заданы не все три переменные
- **THEN** этот пользователь не создаётся, другой пользователь сидится по своим полным переменным
