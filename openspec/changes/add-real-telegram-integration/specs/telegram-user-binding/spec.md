# Spec Delta

## Purpose

Назначение пользователю активной цели переписки (Telegram-бот или мок-сервер) со стороны админа и привязка Telegram-аккаунта пользователя к назначенному боту через ссылку запуска с одноразовым токеном.

## ADDED Requirements

### Requirement: Активная цель пользователя — бот или мок-сервер

Система SHALL хранить для каждого пользователя активную цель переписки: конкретный Telegram-бот либо мок-сервер. Значением по умолчанию SHALL быть мок-сервер (прежнее поведение без Telegram-моста). Админ SHALL назначать и менять цель у любого пользователя.

#### Scenario: Назначение бота

- **WHEN** админ назначает пользователю одного из своих ботов в качестве активной цели
- **THEN** ответ `200`, и у пользователя зафиксирован этот бот как активная цель

#### Scenario: Переключение на мок-сервер

- **WHEN** админ переключает пользователя на мок-сервер
- **THEN** ответ `200`, активная цель — мок-сервер, Telegram-мост для пользователя прекращается

#### Scenario: По умолчанию мок-сервер

- **WHEN** пользователь создан и цель ему явно не назначалась
- **THEN** его активная цель — мок-сервер

#### Scenario: Нельзя назначить чужого или несуществующего бота

- **WHEN** админ пытается назначить пользователю бота, которым он не владеет, или несуществующего бота
- **THEN** запрос отклоняется с ошибкой, цель не изменяется

#### Scenario: Требование роли ADMIN

- **WHEN** назначение цели выполнено без ключа либо ключом не-админа
- **THEN** ответ `401` без ключа и `403` для не-админа

### Requirement: Сброс привязки при смене цели

При смене активной цели (с бота на мок-сервер или на другого бота) система SHALL сбрасывать ранее привязанный Telegram-идентификатор пользователя; мост не возобновится, пока пользователь не выполнит запуск заново.

#### Scenario: Смена бота на мок-сервер снимает привязку

- **WHEN** у пользователя был привязан Telegram-аккаунт и админ переключил его на мок-сервер
- **THEN** привязанный Telegram-идентификатор сброшен, исходящие в Telegram не доставляются

#### Scenario: Смена одного бота на другого снимает привязку

- **WHEN** у пользователя был привязан аккаунт к боту A и админ назначил ему бота B
- **THEN** привязка к боту A сброшена, пока пользователь не выполнит запуск бота B

### Requirement: Запуск бота и deep-link-привязка Telegram-аккаунта

Когда активная цель пользователя — Telegram-бот, система SHALL предоставить способ запустить бота и привязать Telegram-аккаунт к аккаунту пользователя: по запросу выдаётся ссылка запуска с одноразовым токеном; когда бот получает команду запуска с этим токеном через вебхук, система SHALL связать идентификатор чата Telegram с этим пользователем и этим ботом.

#### Scenario: Запрос запуска возвращает ссылку с токеном

- **WHEN** пользователь с активной целью-ботом запрашивает запуск бота
- **THEN** ответ содержит ссылку запуска с уникальным токеном привязки

#### Scenario: Команда запуска привязывает аккаунт

- **WHEN** бот через вебхук получает команду запуска с корректным нерасходованным токеном
- **THEN** идентификатор чата Telegram связывается с пользователем-владельцем токена и этим ботом, и дальнейшие сообщения пользователя проксируются

#### Scenario: Повторный запуск идемпотентен

- **WHEN** пользователь с уже привязанным к этому боту аккаунтом запрашивает запуск повторно
- **THEN** привязка остаётся действующей, повторная команда запуска не создаёт дублей

#### Scenario: Невалидный или истёкший токен не привязывает

- **WHEN** бот получает команду запуска с токеном, который не существует, уже использован или просрочен
- **THEN** привязка не выполняется

#### Scenario: Запуск недоступен без цели-бота

- **WHEN** пользователь с активной целью «мок-сервер» запрашивает запуск бота
- **THEN** запрос отклоняется с ошибкой, ссылка не выдаётся

### Requirement: Кнопка запуска в навигации пользователя

Фронтенд SHALL показывать в навигации пользователя кнопку «Запустить телеграм бота» только тогда, когда его активная цель — Telegram-бот, и скрывать её, когда цель — мок-сервер. Нажатие инициирует запуск и привязку.

#### Scenario: Цель — бот, кнопка видна

- **WHEN** у вошедшего пользователя активная цель — Telegram-бот
- **THEN** в навигации отображается кнопка «Запустить телеграм бота»

#### Scenario: Цель — мок-сервер, кнопка скрыта

- **WHEN** у вошедшего пользователя активная цель — мок-сервер
- **THEN** кнопка «Запустить телеграм бота» в навигации отсутствует

#### Scenario: Нажатие открывает ссылку запуска

- **WHEN** пользователь нажимает кнопку «Запустить телеграм бота»
- **THEN** приложение получает ссылку запуска и переходит по ней (открывается чат бота в Telegram)
