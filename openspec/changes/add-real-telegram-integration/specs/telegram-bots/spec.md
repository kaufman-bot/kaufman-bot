# Spec Delta

## Purpose

Управление несколькими реальными Telegram-ботами на стороне админа: создание, изменение, удаление, включение/выключение, индивидуальные настройки, собственный адрес вебхука и самостоятельная регистрация вебхука каждого включённого бота при старте приложения.

## ADDED Requirements

### Requirement: CRUD Telegram-ботов с ограничением по владельцу

Система SHALL предоставлять эндпоинты под ролью `ADMIN` для создания, просмотра, изменения и удаления Telegram-ботов. Каждый бот SHALL принадлежать создавшему его админу, и админ SHALL видеть, изменять и удалять только собственных ботов.

#### Scenario: Создание бота

- **WHEN** админ создаёт бота с токеном, именем и набором настроек
- **THEN** ответ `201` возвращает созданного бота, и он появляется в списке этого админа

#### Scenario: Список ограничивается владельцем

- **WHEN** админ запрашивает список своих ботов
- **THEN** ответ содержит только ботов, созданных этим админом, без ботов других админов

#### Scenario: Чужой бот недоступен

- **WHEN** админ обращается к боту, владельцем которого он не является
- **THEN** ответ `404`, данные не изменяются

#### Scenario: Изменение бота

- **WHEN** админ изменяет имя, настройки или токен своего бота
- **THEN** ответ `200` возвращает обновлённого бота с новыми значениями

#### Scenario: Удаление бота

- **WHEN** админ удаляет своего бота
- **THEN** ответ `204`, бот исчезает из списка владельца

#### Scenario: Требование роли ADMIN

- **WHEN** запрос к эндпоинтам ботов выполнен без ключа либо ключом пользователя без роли `ADMIN`
- **THEN** ответ `401` без ключа и `403` для не-админа

### Requirement: Хранение токена и настроек бота

Каждый бот SHALL хранить секретный токен Bot API и именованный набор настроек. Секретный токен SHALL возвращаться наружу только в маскированном виде; значения прочих настроек SHALL быть доступны владельцу.

#### Scenario: Токен маскируется

- **WHEN** админ читает бота или список своих ботов
- **THEN** токен возвращается в маскированном виде, полное значение не раскрывается

#### Scenario: Настройки сохраняются и возвращаются

- **WHEN** админ задаёт боту набор настроек и затем перечитывает его
- **THEN** сохранённые значения настроек возвращаются без изменений

### Requirement: Включение и выключение бота

Админ SHALL включать и выключать своего бота флагом активности. Выключенный бот не принимает входящие обновления Telegram и не отправляет исходящие сообщения.

#### Scenario: Выключение бота

- **WHEN** админ выключает включённого бота
- **THEN** ответ `200` с `isActive=false`, и последующие обновления для него не обрабатываются

#### Scenario: Включение бота

- **WHEN** админ включает выключенного бота
- **THEN** ответ `200` с `isActive=true`

### Requirement: Собственный вебхук и самостоятельная регистрация при старте

Каждый включённый бот SHALL иметь собственный публичный адрес вебхука с секретом. При старте приложения система SHALL пытаться зарегистрировать вебхук каждого включённого бота; сбой регистрации SHALL фиксироваться в логах и не прерывать запуск приложения и других ботов. Входящий запрос на адрес вебхука SHALL проверяться по секрету бота.

#### Scenario: Регистрация вебхука при старте

- **WHEN** приложение стартует и есть включённые боты
- **THEN** для каждого включённого бота выполняется попытка зарегистрировать его собственный вебхук

#### Scenario: Сбой регистрации не блокирует запуск

- **WHEN** регистрация вебхука одного бота завершается ошибкой (сеть или Telegram недоступен)
- **THEN** приложение продолжает запуск, остальные боты обрабатываются, ошибка залогирована

#### Scenario: Входящий вебхук проверяется секретом

- **WHEN** на адрес вебхука приходит запрос без корректного секрета этого бота
- **THEN** запрос отклоняется, и сообщение не обрабатывается
