# Spec Delta

## MODIFIED Requirements

### Requirement: Отправка сообщения пользователем

Система SHALL предоставлять эндпоинт `POST /api/v1/chat/messages` (доступ по API-ключу), который добавляет сообщение отправителя `USER` в диалог вошедшего пользователя с ботом и возвращает созданное сообщение. Если активная цель пользователя — выключенный Telegram-бот, отправка SHALL возвращать понятную ошибку и не сохранять сообщение.

#### Scenario: Успешная отправка

- **WHEN** пользователь с валидным ключом отправляет непустой текст
- **THEN** ответ `201` содержит созданное сообщение (отправитель `USER`), и оно сохранено в его диалоге

#### Scenario: Пустое или отсутствующее сообщение

- **WHEN** текст сообщения пуст, состоит из пробелов или поле отсутствует
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Превышение максимальной длины

- **WHEN** текст сообщения длиннее 4000 символов
- **THEN** ответ `400` с телом ошибки, сообщение не сохраняется

#### Scenario: Запрос без валидного ключа

- **WHEN** запрос выполнен без API-ключа или с недействительным ключом
- **THEN** ответ `401` с телом ошибки

#### Scenario: Отправка при выключенном привязанном боте

- **WHEN** активная цель пользователя — Telegram-бот и этот бот выключен, и пользователь отправляет текст из веб-чата
- **THEN** ответ `409` с понятным текстом ошибки, сообщение не сохраняется и не передаётся плагинам

#### Scenario: Отправка при включённом привязанном боте

- **WHEN** активная цель пользователя — включённый Telegram-бот и пользователь отправляет непустой текст из веб-чата
- **THEN** ответ `201`, сообщение сохранено в диалоге, а последующий ответ бота дополнительно пересылается пользователю в Telegram

### Requirement: Отправка callback_data по нажатию кнопки

Когда пользователь нажимает кнопку сообщения бота, фронтенд SHALL отправить её `callback_data` на сервер от имени вошедшего пользователя; сервер SHALL сохранить это как сообщение отправителя `USER` в диалоге пользователя. Если активная цель пользователя — выключенный Telegram-бот, нажатие SHALL возвращать понятную ошибку и не сохраняться.

#### Scenario: Нажатие сохраняет коллбэк оператору

- **WHEN** пользователь нажимает кнопку с `callback_data`
- **THEN** в диалоге создаётся сообщение отправителя `USER` с текстом `callback_data`, доступное оператору в консоли

#### Scenario: Нажатие при выключенном привязанном боте

- **WHEN** активная цель пользователя — выключенный Telegram-бот и пользователь нажимает кнопку в веб-чате
- **THEN** ответ `409` с понятным текстом ошибки, коллбэк не сохраняется и не передаётся плагинам

#### Scenario: Нажатие при включённом привязанном боте

- **WHEN** активная цель пользователя — включённый Telegram-бот и нажатый payload обрабатывается плагином
- **THEN** ответ бота на это нажатие дополнительно пересылается пользователю в Telegram
