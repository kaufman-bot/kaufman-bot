# Spec Delta

## Purpose

Плагинная архитектура ответов бота: реакции на сообщения пользователя оформлены как подключаемые сервисы-плагины с единым контрактом, регистрируемые под общим токеном провайдера; ядро чата находит подходящий плагин и доставляет его ответ пользователю.

## ADDED Requirements

### Requirement: Единый контракт и общий токен провайдера плагинов

Система SHALL определять единый интерфейс плагина бота (проверка применимости к сообщению и вычисление ответа) и SHALL собирать все зарегистрированные плагины по одному общему токену провайдера (multi-provider). Добавление нового плагина SHALL сводиться к добавлению его сервиса-реализации и регистрации под этим токеном — без изменения ядра обработки сообщений чата.

#### Scenario: Несколько плагинов под одним токеном

- **WHEN** в приложении зарегистрированы несколько сервисов-плагинов под общим токеном провайдера
- **THEN** все они доступны диспетчеру ответов как единый список плагинов, и каждый участвует в обработке сообщений пользователей

#### Scenario: Порядок плагинов определяется порядком регистрации

- **WHEN** сообщение пользователя подходит под условия нескольких плагинов
- **THEN** плагины рассматриваются в порядке их регистрации в конфигурации приложения

### Requirement: Автоответ плагина на сообщение пользователя

Когда пользователь отправляет сообщение в свой диалог, система SHALL передавать его плагинам; если условие срабатывания какого-либо плагина выполнено, ответ этого плагина SHALL быть доставлен пользователю как обычное сообщение бота: сохранён в его диалоге, возвращается в истории и доставляется подключённому клиенту через существующий SSE-поток чата.

#### Scenario: Плагин срабатывает на сообщение

- **WHEN** пользователь с валидным ключом отправляет сообщение, под которое подписан один из плагинов
- **THEN** в его диалоге появляется новое сообщение бота с текстом, вычисленным плагином, отправитель — `BOT`

#### Scenario: Ответ виден в истории и консоли мок-сервера

- **WHEN** плагин ответил на сообщение пользователя
- **THEN** ответ отображается в истории диалога пользователя, в списке диалогов консоли мок-сервера и доставляется по SSE как событие сообщения бота

#### Scenario: Ни один плагин не сработал

- **WHEN** пользователь отправляет сообщение, не подходящее ни под один плагин
- **THEN** сообщение пользователя сохранено и доставлено как обычно, автоматического ответа бота нет

### Requirement: Один ответ на сообщение пользователя

На одно сообщение пользователя система SHALL отправлять не более одного ответа плагина: обрабатывается только первый плагин, чьё условие срабатывания выполнено.

#### Scenario: Пересечение условий нескольких плагинов

- **WHEN** сообщение пользователя подходит условиям более чем одного плагина
- **THEN** отвечает только первый сработавший плагин; остальные плагины для этого сообщения не вызываются

### Requirement: Сообщения бота не триггерят плагины

Плагины SHALL обрабатывать только сообщения с ролью отправителя `USER`. Ответы бота, включая сообщения оператора из консоли мок-сервера и ответы других плагинов, SHALL не вызывать срабатывание плагинов.

#### Scenario: Ответ оператора из консоли мок-сервера

- **WHEN** оператор отправляет ответ от имени бота, текст которого совпадает с условием срабатывания плагина
- **THEN** плагин не срабатывает и дополнительного сообщения в диалоге не появляется

### Requirement: Изоляция ошибок плагинов

Ошибка при работе плагина SHALL не нарушать отправку сообщения пользователя и работу других частей API: сообщение пользователя сохраняется, клиент получает успешный ответ отправки, автоматический ответ просто не добавляется.

#### Scenario: Падение плагина при обработке

- **WHEN** плагин выбрасывает ошибку при обработке сообщения пользователя
- **THEN** HTTP-ответ отправки сообщения остаётся успешным, сообщение пользователя сохранено в диалоге, ответа бота нет, а факт ошибки зафиксирован в журнале приложения
