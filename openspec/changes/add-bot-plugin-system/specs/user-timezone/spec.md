# Spec Delta

## Purpose

Хранение таймзоны пользователя: необязательная таймзона (IANA) в профиле, самообновление профиля владельцем ключа и автосинхронизация таймзоны браузера с фронтенда. Используется плагинами для привязки времени сервера к локальному времени пользователя.

## ADDED Requirements

### Requirement: Таймзона в модели пользователя

У каждого пользователя SHALL быть необязательная таймзона (строка в формате IANA, например `Europe/Moscow`); по умолчанию она не задана (null). Изменение схемы БД SHALL выполняться только миграцией Prisma.

#### Scenario: Новый пользователь без таймзоны

- **WHEN** создаётся аккаунт (регистрация или сид) без указания таймзоны
- **THEN** таймзона пользователя не задана (null), аккаунт работает как прежде

### Requirement: Таймзона в ответах профиля

Ответы `GET /api/v1/auth/me` и `POST /api/v1/auth/login` SHALL включать поле `timezone` пользователя (строка IANA или null) в составе части «пользователь» профиля.

#### Scenario: Профиль с заданной таймзоной

- **WHEN** у пользователя задана таймзона и запрашивается профиль
- **THEN** ответ содержит `timezone` с сохранённым значением IANA

#### Scenario: Профиль без таймзоны

- **WHEN** у пользователя таймзона не задана и запрашивается профиль
- **THEN** ответ содержит `timezone: null`

### Requirement: Самообновление профиля по ключу

Система SHALL предоставлять эндпоинт `PATCH /api/v1/auth/me` (доступ по API-ключу), который обновляет профиль владельца предъявленного ключа. Тело запроса содержит необязательное поле `timezone`: при передаче значение SHALL валидироваться как таймзона IANA и сохраняться; повторная передача `null` SHALL очищать таймзону. Ответ — профиль в том же контракте, что и `GET /api/v1/auth/me`.

#### Scenario: Обновление таймзоны

- **WHEN** владелец валидного ключа отправляет `PATCH /api/v1/auth/me` с `timezone: "Europe/Moscow"`
- **THEN** ответ `200` содержит обновлённый профиль с `timezone: "Europe/Moscow"`, значение сохранено для пользователя

#### Scenario: Очистка таймзоны

- **WHEN** владелец валидного ключа отправляет `PATCH /api/v1/auth/me` с `timezone: null`
- **THEN** ответ `200` содержит профиль с `timezone: null`, сохранённое значение удалено

#### Scenario: Невалидная таймзона

- **WHEN** в теле `PATCH /api/v1/auth/me` передана строка, не являющаяся таймзоной IANA (например `Mars/Olympus`)
- **THEN** ответ `400` с телом ошибки, таймзона не меняется

#### Scenario: Запрос без валидного ключа

- **WHEN** `PATCH /api/v1/auth/me` вызван без API-ключа или с недействительным ключом
- **THEN** ответ `401` с телом ошибки, профиль не меняется

### Requirement: Автосинхронизация таймзоны с фронтенда

После входа по API-ключу и при восстановлении сессии фронтенд SHALL определять таймзону браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`) и, если она отличается от сохранённой в профиле, отправлять её в `PATCH /api/v1/auth/me`. Синхронизация SHALL не блокировать работу страниц и SHALL не прерывать сессию при её неудаче.

#### Scenario: Первый вход из новой таймзоны

- **WHEN** пользователь входит по ключу, а таймзона браузера отличается от таймзоны в профиле
- **THEN** фронтенд отправляет `PATCH /api/v1/auth/me` с таймзоной браузера, профиль обновлён

#### Scenario: Таймзона совпадает

- **WHEN** таймзона браузера совпадает с сохранённой в профиле
- **THEN** `PATCH /api/v1/auth/me` не вызывается

#### Scenario: Ошибка синхронизации не мешает работе

- **WHEN** запрос синхронизации таймзоны завершился ошибкой сети
- **THEN** пользователь остаётся в сессии, страницы чата и дашборда работают без изменений
