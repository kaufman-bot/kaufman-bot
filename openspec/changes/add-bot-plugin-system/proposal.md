# Proposal

## Why

Диалоговая логика бота сейчас жёстко зашита: на сообщение пользователя бот отвечает только через консоль мок-сервера (вручную оператором). Чтобы развивать бота как платформу, реакции на сообщения пользователя нужно вынести в подключаемые плагины — независимые сервисы с единым контрактом, которые можно добавлять, не трогая ядро чата. Базовая механика нужна сейчас, чтобы на её месте выросли будущие навыки бота; первыми плагинами будут простые демо-реакции: «ping» → «pong» и «time» → текущее время сервера в таймзоне пользователя.

## What Changes

- **Плагинная система сервисов (бэкенд)**: единый интерфейс плагина и общий токен провайдера; каждый плагин — отдельный NestJS-сервис, зарегистрированный под этим токеном в `AppModule` (multi-provider). Новый сервис-диспетчер собирает все плагины по токену и при каждом сообщении пользователя в чате находит первый плагин, который может ответить, и отправляет его ответ от имени бота (сохранение в диалог + публикация в SSE-поток чата).
- **Плагин «ping»**: на сообщение пользователя с текстом `ping` (после trim, без учёта регистра) бот отвечает `pong`.
- **Плагин «time»**: на сообщение пользователя с текстом `time` бот отвечает текущим временем сервера, отформатированным в таймзоне пользователя; при отсутствии таймзоны — в UTC.
- **Таймзона пользователя**: новая колонка `timezone` (nullable, строка) в модели `User` — только через миграцию Prisma; новое эндпоинт `PATCH /api/v1/auth/me` для самообновления профиля (валидация значения как IANA-таймзоны выполняется в сервисе, глобального ValidationPipe в проекте нет); поле `timezone` добавляется в DTO профиля (`AuthProfileUserDto`).
- **Фронтенд**: после входа и при восстановлении сессии клиент автоматически определяет таймзону браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`) и синхронизирует её с профилем, если она отличается.
- **BREAKING**: нет. Контракты существующих эндпоинтов только расширяются (опциональное поле в профиле); ответы плагинов идут в существующий поток чата.
- Telegram-интеграция остаётся вне рамок этой задачи.

Допущения, принятые без отдельного вопроса:

- На одно сообщение пользователя отвечает не более одного плагина: побеждает первый по порядку регистрации, чей матчинг сработал. Сообщения оператора из консоли мок-сервера плагины не триггерят (это ответы бота, а не сообщения пользователя).
- Матчинг «ping»/«time» — точное совпадение текста после trim без учёта регистра; частичное вхождение не срабатывает.
- Если ни один плагин не сработал, поведение чата не меняется (ответа бота нет); ошибка плагина не ломает отправку сообщения пользователя (лог + ответ без автоответа).
- Ответ плагина — обычное сообщение `BOT` в диалоге пользователя: сохраняется в БД и доставляется по SSE, виден и в консоли мок-сервера.

## Capabilities

### New Capabilities

- `bot-plugin-system`: плагинная архитектура ответов бота — единый интерфейс плагина и токен провайдера, multi-provider регистрация плагинов в `AppModule`, диспетчер, встраивающий плагины в поток сообщений чата, и правила изоляции ошибок плагинов.
- `user-timezone`: хранение таймзоны пользователя — колонка в `User`, самообновление профиля через `PATCH /api/v1/auth/me`, таймзона в DTO профиля, автосинхронизация таймзоны браузера с фронта.
- `ping-pong-plugin`: поведение плагина-эха — ответ `pong` на сообщение `ping`.
- `time-plugin`: поведение плагина времени — ответ текущим временем сервера в таймзоне пользователя на сообщение `time`.

## Impact

- **Бэкенд** (`backend/`): новая миграция Prisma (колонка `timezone` в `users`); новый интерфейс плагина + токен провайдера и два плагина-сервиса; новый сервис-диспетчер; расширение `ChatService.sendMessage` (вызов диспетчера после сохранения сообщения пользователя); новый метод `AuthService` (обновление профиля) и `PATCH /auth/me` в `AuthController` с DTO со Swagger-декораторами; расширение `AuthProfileUserDto` полем `timezone`; регистрация всех новых провайдеров в `AppModule` (в том числе multi-provider по токену плагинов).
- **Фронтенд** (`frontend/`): автосинхронизация таймзоны в `SessionService` после входа и восстановления сессии (вызов `PATCH /auth/me`); обновление типов профиля; юнит-тесты (Jest).
- **Схема БД**: миграция `add_timezone_to_users` (nullable `String`, без NOT NULL — обратная совместимость с существующими записями).
- **Swagger/SDK**: перегенерация `swagger.json` → сгенерированный OpenAPI SDK для e2e (`npm run start:dev` → `npm run generate:openapi-ts`).
- **Тесты**: юнит-тесты диспетчера и плагинов (Vitest, моки Prisma/событийной шины); e2e через сгенерированный SDK на реальном бэкенде: `ping`→`pong`, `time`→время в таймзоне профиля, валидация `PATCH /auth/me` (400 на не-IANA значение); юнит-тесты фронта на синхронизацию таймзоны.
