# Proposal

## Why

Бот умеет отвечать плагинами (time, settings), но не решает прикладную задачу заказа такси: у оператора нет ни справочников маршрутов и цен, ни витрины заказов. Нужен плагин такси с пошаговым визардом в чате и отдельная админка для управления всеми данными такси (города, услуги, цены, водители, заказы).

## What Changes

- Новый плагин `taxi`: команда `/taxi` запускает последовательный визард заказа (откуда → куда → время выезда → кол-во человек → доп. услуги → подтверждение) через inline-кнопки в namespace `taxi:`; заказ сохраняется с ценой из матрицы.
- Автоназначение машины: при подтверждении заказа система автоматически подбирает свободную машину с водителем, удовлетворяющую запросу пассажира (вместимость не меньше кол-ва человек и заявленные возможности машины — детское кресло, курение в салоне и т.п.); подобранная машина фиксируется в заказе и показывается пассажиру и в админке.
- Админ-API такси: CRUD населённых пунктов, доп. услуг, времени выезда, кол-ва человек, водителей с их машинами; матрица цен по парам городов с кнопкой авторасчёта по километражу; список заказов со сменой статуса. Всё под `ApiKeyGuard` + `AdminGuard`.
- Сид данных по умолчанию: Москва и Санкт-Петербург + крупные города между ними (с километражем), типовые доп. услуги (детское кресло, курение в салоне, музыка, и т.п.), слоты времени выезда, варианты кол-ва человек.
- Админка на фронте: новый пункт «Такси» в навигации (только ADMIN), страница `/taxi` с сайдбаром (справочники, матрица цен, водители, заказы) и дочерними маршрутами на каждый CRUD.
- Страница «Заказы» внутри `/taxi`: текущие заказы такси (кто, откуда→куда, когда, пассажиры, услуги, цена, статус) со сменой статуса.

Допущения (зафиксированы, не критичны для скоупа):

- «таски с их машинами» читается как «тачки»: CRUD водителей, у каждого водителя вложенный список его машин.
- Страница заказов — просмотр + смена статуса (типовой минимум операционной работы); без редактирования состава заказа.
- Справочники такси глобальные (не владелец-скоупед), доступ на изменение — любой ADMIN.
- Авторасчёт — линейная пропорция цены за км, введённой по крайним пунктам маршрута.
- Время выезда — набор ежедневных слотов (строка `HH:MM`), без календарных дат; кол-во человек — список допустимых значений.
- Оплата и ручное распределение заказов вне скоупа: машина подбирается автоматически при подтверждении заказа; «свободна» = у машины нет активного заказа (`NEW`/`CONFIRMED`), время слотов не учитывается (упрощение первой версии — design D11).
- Часть доп. услуг — «возможности машины»: админ помечает такие услуги признаком (детское кресло, курение, музыка и т.п.), а машина декларирует, какие из них предоставляет; автоподбор учитывает только возможности-услуги и вместимость.

## Capabilities

### New Capabilities

- `taxi-catalog-admin`: админские справочники такси — населённые пункты (с километражем), доп. услуги (с наценкой и признаком «возможность машины»), время выезда, кол-во человек, водители со своими машинами (машина декларирует предоставляемые возможности-услуги для автоподбора); CRUD для каждого.
- `taxi-price-matrix`: матрица цен по парам населённых пунктов: ручное редактирование и авторасчёт всех пар по цене между крайними пунктами и километражу.
- `taxi-orders-admin`: админская страница текущих заказов такси: просмотр (пассажир, маршрут, время, услуги, цена, статус, назначенная машина с водителем) и смена статуса; завершение/отмена заказа освобождает машину.
- `taxi-order-wizard`: визард заказа такси в чате бота — последовательные шаги на inline-кнопках, черновик заказа, расчёт цены и автоподбор свободной машины на подтверждении, сохранение заказа.

## Impact

- **БД** (`backend/prisma/`): новые модели `TaxiCity`, `TaxiExtraService`, `TaxiCityPrice`, `TaxiDepartureSlot`, `TaxiPassengerOption`, `TaxiDriver`, `TaxiCar`, `TaxiOrder` (+ enum статуса, оснащение машин возможностями и ссылка заказа на машину) — только аддитивная миграция.
- **Бэкенд** (`backend/src/`): новый плагин `plugins/taxi.plugin.ts` (первый многшаговый визард — хранит черновик заказа в БД), сервисы такси включая use-case автоподбора машины, контроллеры + DTO со Swagger, регистрация в `app.module.ts` (контроллеры/сервисы/фабрика `BOT_PLUGINS`), сид дефолтных справочников.
- **Контракт**: `swagger.json` → перегенерация SDK `generate:openapi-ts`.
- **Фронтенд** (`frontend/src/app/`): пункт navbar «Такси» (ADMIN), `TaxiAdminLayout` с сайдбаром + 7 дочерних страниц, `taxi.service.ts` на SDK.
- **Тесты**: юнит (Vitest) — плагин/сервисы, матрица и авторасчёт; e2e (SDK, живой бэкенд) — CRUD справочников и матрицы, визард через чат; Jest — фронт-компоненты. E2E не трогают сидовые справочники (test-spawned ключи, cleanup своих записей — `.agents/skills/e2e-fixture-hygiene/SKILL.md`).
- **Документация**: `backend/README.md`, `frontend/README.md`, `docs/architecture.md` — раздел такси.
