# Spec Delta

## Purpose

Матрица цен такси: стоимость поездки для каждой пары населённых пунктов, ручное редактирование любой пары и авторасчёт всех пар по цене между крайними пунктами маршрута. Цены матрицы использует визард заказа.

## ADDED Requirements

### Requirement: Просмотр матрицы цен

Система SHALL предоставлять эндпоинт `GET /api/v1/taxi/price-matrix` (доступ по API-ключу с ролью ADMIN), который возвращает упорядоченные по километражу населённые пункты и список цен пар. Пара SHALL задаваться двумя идентификаторами пунктов и ценой (неотрицательное целое число рублей); каждая неупорядоченная пара хранится в матрице один раз и отображается один раз.

#### Scenario: Чтение матрицы

- **WHEN** ADMIN запрашивает матрицу после создания цен
- **THEN** ответ `200` содержит города с километражем и сохранённые цены пар

### Requirement: Ручное редактирование цены пары

Система SHALL предоставлять эндпоинт `PUT /api/v1/taxi/price-matrix/:fromCityId/:toCityId` для установки цены пары (создание или обновление). Цена пары SHALL быть симметричной: значение одной и той же цены возвращается независимо от порядка пунктов в запросе. Цена SHALL быть неотрицательным целым числом.

#### Scenario: Установка цены пары

- **WHEN** ADMIN устанавливает цену для пары «Москва → Санкт-Петербург»
- **THEN** ответ `200` содержит цену, и чтение пары в обратном порядке «Санкт-Петербург → Москва» возвращает ту же цену

#### Scenario: Некорректная цена

- **WHEN** ADMIN отправляет отрицательную или дробную цену, или `fromCityId` равен `toCityId`
- **THEN** ответ `400`, цена не сохраняется

#### Scenario: Несуществующий пункт

- **WHEN** ADMIN устанавливает цену для пары с несуществующим идентификатором пункта
- **THEN** ответ `404`

### Requirement: Авторасчёт матрицы по крайним пунктам

Система SHALL предоставлять эндпоинт `POST /api/v1/taxi/price-matrix/auto-calc`, который принимает цену поездки между самыми крайними пунктами маршрута (минимальный и максимальный километраж) и SHALL создать или обновить цены для всех пар пунктов: цена каждой пары пропорциональна разности их километража (цена за километр = введённая цена ÷ расстояние между крайними пунктами, результат округляется до целого рубля).

#### Scenario: Расчёт для маршрута с промежуточными пунктами

- **WHEN** ADMIN вводит цену между крайними пунктами маршрута и запускает авторасчёт
- **THEN** цены созданы для всех пар пунктов, включая пары с промежуточными пунктами; пара крайних пунктов получает введённую цену (с точностью до округления)

#### Scenario: Существующие цены перезаписываются

- **WHEN** авторасчёт запущен, когда часть пар уже имеет цены
- **THEN** цены всех пар пересчитаны заново по введённому значению, а не суммированы с прежними

#### Scenario: Меньше двух пунктов

- **WHEN** авторасчёт запущен, когда в справочнике менее двух активных пунктов
- **THEN** ответ `400` с пояснением, что для расчёта нужны минимум два пункта

### Requirement: Доступ к матрице только для админов

Эндпоинты матрицы цен SHALL требовать API-ключ и роль ADMIN: без ключа — `401`, с не-админским ключом — `403`.

#### Scenario: Не-админский ключ

- **WHEN** запрос выполнен с валидным ключом пользователя с ролью USER
- **THEN** ответ `403` с телом ошибки
