# Spec Delta

## Purpose

Операционная витрина заказов такси: список оформленных в боте заказов с параметрами поездки и ценой, фильтр по статусу и смена статуса. Позволяет оператору видеть текущие заказы и вести их до завершения.

## ADDED Requirements

### Requirement: Список заказов такси

Система SHALL предоставлять эндпоинт `GET /api/v1/taxi/orders` (доступ по API-ключу с ролью ADMIN), возвращающий оформленные заказы (кроме черновиков визарда) в порядке убывания времени оформления. Поддержан фильтр по статусу; без явного фильтра SHALL возвращаться только активные заказы.

#### Scenario: Просмотр текущих заказов

- **WHEN** пассажир оформил заказ через визард и ADMIN открывает список заказов
- **THEN** заказ отображается со статусом `NEW` и полным составом: пассажир (пользователь и его email), маршрут, время выезда, кол-во человек, доп. услуги, базовая и итоговая цена, назначенная машина (модель, госномер, водитель), время оформления

#### Scenario: Дефолтный фильтр по статусу

- **WHEN** ADMIN запрашивает список без явного фильтра
- **THEN** возвращаются только заказы в статусах `NEW` и `CONFIRMED`; завершённые и отменённые видны только при явном фильтре

#### Scenario: Черновики не видны

- **WHEN** пользователь остановился посреди визарда (существует незавершённый черновик) и ADMIN запрашивает список заказов
- **THEN** черновик в списке отсутствует

### Requirement: Смена статуса заказа

Система SHALL предоставлять эндпоинт `PATCH /api/v1/taxi/orders/:id` для смены статуса заказа между `NEW`, `CONFIRMED`, `COMPLETED` и `CANCELLED`. Заказ в статусе `NEW` или `CONFIRMED` SHALL удерживать назначенную ему машину занятой; перевод заказа в `COMPLETED` или `CANCELLED` SHALL освобождать машину для подбора новым заказом. Попытка смены статуса несуществующего заказа SHALL отвечать `404`, неизвестное значение статуса — `400`.

#### Scenario: Подтверждение заказа

- **WHEN** ADMIN меняет статус заказа `NEW` → `CONFIRMED`
- **THEN** ответ `200` содержит заказ с новым статусом

#### Scenario: Освобождение машины

- **WHEN** ADMIN переводит заказ в `COMPLETED` или `CANCELLED`
- **THEN** назначенная заказу машина освобождается и может быть подобрана следующему заказу

#### Scenario: Неизвестный статус

- **WHEN** ADMIN отправляет значение статуса вне перечисленных
- **THEN** ответ `400`, статус не меняется

### Requirement: Стабильность снимка заказа

Оформленный заказ SHALL хранить снимок своих параметров (названия пунктов, время выезда, перечень услуг с наценками, цены): последующие правки или удаления справочников SHALL не менять параметры и отображение уже оформленных заказов.

#### Scenario: Правка справочника после заказа

- **WHEN** ADMIN переименовывает пункт отправления или удаляет доп. услугу после оформления заказа
- **THEN** ранее оформленный заказ отображает исходные названия и цены на момент подтверждения

### Requirement: Доступ к заказам только для админов

Эндпоинты заказов SHALL требовать API-ключ и роль ADMIN: без ключа — `401`, с не-админским ключом — `403`.

#### Scenario: Не-админский ключ

- **WHEN** запрос выполнен с валидным ключом пользователя с ролью USER
- **THEN** ответ `403` с телом ошибки

### Requirement: Страница заказов в админке такси

Фронтенд SHALL отображать страницу «Заказы» внутри раздела «Такси» (пункт сайдбара): таблицу заказов с колонками пассажира, маршрута, времени выезда, пассажиров, услуг, цены и статуса, фильтром по статусу и управлением статусом из строки таблицы. Доступ SHALL быть только у вошедших ADMIN.

#### Scenario: Открытие страницы

- **WHEN** ADMIN открывает раздел «Такси» → «Заказы»
- **THEN** отображается таблица текущих заказов с данными последнего оформленного заказа

#### Scenario: Доступ не-админа

- **WHEN** пользователь с ролью USER открывает страницу заказов
- **THEN** доступ запрещён гардом маршрута
